Date: 2026-09-01 · Repo: `D:\Downloads\Digital scribbl` · Branch: `scribble-core-rework`

## Verdict

**The v1 app is real, working, and frozen.** ~23k LOC, 24 pages, 33 API routes, type-check clean, 63/63 tests passing. It is not broken — but it is built for a story that has already expired (college ended May 2026).

**The v2 rebuild is fully specified and zero-percent built.** `docs/v2/` is an excellent 7-doc spec with an 8-phase plan. Only Phase 0 (spec) is in progress. Phases 1–7 are untouched.

**The gap that matters:** the v2 timeline targets *"ship scribble early September 2026."* That is this week. Phase 1 — the new Supabase project — does not exist. Phase 2 (auth + onboarding + first shirt) is what actually ships the product, and it depends on Phase 1. **The stated ship date is not achievable from here.**

## 2. What's genuinely good

- **Auth defence-in-depth is correct.** `proxy.ts` deliberately skips `/api/*`, and every one of the 30 API routes independently re-checks via `requireApiUser()`. No API route is reachable unauthenticated. All 4 admin routes double-check `getUserIsAdmin()` and return 403.
- **No unauthenticated service-role path exists.** 28 routes use the RLS-bypassing client, always *after* an auth check. The 3 exceptions (OAuth callback, dev bypass, logout) are all correctly justified.
- **Uploads are properly hardened.** `app/api/avatar/upload-head/route.ts:50-63` sniffs magic bytes with `file-type` (never trusts client MIME), caps size, and re-encodes through Sharp. There's an SVG sanitizer at `lib/utils/sanitizeSvg.ts`.
- **No SQL injection surface.** Zero `.rpc()` calls, zero string-interpolated SQL, no dynamic `EXECUTE` in migrations.
- **No secrets committed.** `.env.local` is correctly gitignored; `git ls-files` returns only `.env.local.example`. Service-role key is never `NEXT_PUBLIC_`-prefixed.
- **All 6 P0 studio bugs from doc 23 are verified fixed** in code (canvas rebuild per stroke, retina scaling, draft persistence, eraser cursor, keyboard shortcuts, publish-clears-canvas).
- **Doc 22 S6 (onboarding trusted the client) is verified fixed** — onboarding now POSTs to a Zod-validated route.

## 3. Findings by severity

### P1 — High (3, all independently verified)

**P1-1 · `yearbook_renders` has no RLS.**
`supabase/migrations/010_role_access_lifecycle.sql:238` creates it; no `enable row level security` anywhere in 001–013. I diffed all 27 `create table` against all 26 `enable row level security` statements — this is the **only** gap. Holds per-user `front_png_url` / `back_png_url`. Fully readable/writable via the public PostgREST API on any anon-key leak. Blast radius is limited only because no client code queries it yet.

**P1-2 · Migration 013 will fail on any database where 010 ran.**
`010:291` drops `batches_program_id_graduation_year_key` and adds `batches_program_year_label_uk unique (program_id, graduation_year, label)`. `013:119-149` inserts with `on conflict (program_id, graduation_year)` — a 2-column conflict target that **no longer exists**. Expect Postgres `42P10` and an aborted migration 013, which also means `program_requests` may not land. This is a deployment/data-integrity failure, not an attack.

**P1-3 · SSRF in the yearbook export — still open from doc 22 §S1.**
`app/api/yearbook/export/route.ts:112` — `await fetch(profile.head_front_url)` with **no host allowlist and no `redirect: 'error'`**. `isAllowedAssetUrl` does not exist anywhere in the repo. Users can write `head_front_url` (granted in migration 008), so a user can point it at `http://169.254.169.254/...` and have the server fetch it. Exploitable whenever an export runs.

### P2 — Medium (4)

**P2-4 · Three-way academic seed conflict — and it's worse than the docs admit.**
All three seeds exist, but critically **010 and 013 are both migrations, so both run in production** (unlike `seed.sql`, which is dev-only):

| Source | Content |
|---|---|
| `supabase/seed.sql:8-27` | Dev-only. 5 programs, 6 batches. Not auto-applied. |
| `010:300-326` | `University` → `B.Tech Computer Science` → **52 batches** (`Batch 01`…`52`), 2026 |
| `013:38-150` | 5 Bennett schools → 6 programs (incl. a **second** `B.Tech Computer Science`) → `Class of 2026` batches |

A fresh DB ends with two hierarchies, two duplicate program names, and two disjoint 2026 batch sets. `canAttemptScribble` (`lib/utils/safetyAccess.ts:41-48`) gates signing on `sameBatch` — so batchmates split across trees are **silently denied the ability to sign each other**. That is the core social guarantee of the product.

**P2-5 · Domain allowlist fails *open* when unset.**
`lib/utils/safetyAccess.ts:15-19` — returns true when `allowedDomains.length === 0`. If `NEXT_PUBLIC_ALLOWED_EMAIL_DOMAINS` is empty or misconfigured, **every** Google signup becomes a verified student with a shirt. Should fail closed.

**P2-6 · Dev auth bypass is public on any non-`production` deploy.**
`lib/auth/dev.ts:31` gates only on `NODE_ENV === 'production'`. `role.ts:55` puts `/dev` in the public route list, and `isPublicRoute` uses `startsWith` — so `app/dev/test-users` and `app/dev/ia-map` are reachable signed-out. With the bypass on, `proxy.ts:61` skips the login redirect and `:75-89` reads the identity via the **service-role** client. Fine in true prod; full unauthenticated access in a misconfigured staging/preview.

**P2-7 · Doc 22 S2 / S3 / S4 all still open.**
- S2 in-memory rate limiting — `lib/utils/rateLimit.ts:23` is a plain `Map`, per-instance, no shared store.
- S3 no security headers / CSP — `next.config.mjs` (19 lines) has no `headers()` block.
- S4 `voice_url` unvalidated — `app/api/scribble/place/route.ts:167` only checks `.startsWith('http')`, no host allowlist.

### P3 — Low (4)

- **`vitest run` hangs after passing.** All 63 tests pass in 3.0s but the process never exits (open handle). CI would hang on a green suite.
- **`proxy.ts:127` redirects to routes that don't exist.** `/guest`, `/u/`, `/i/` are all absent from `app/` — those redirects land on 404s.
- **`lib/supabase/types.ts` (710 lines) is decorative.** Hand-written, and neither `server.ts:7` nor `client.ts:4` applies the `Database` generic — so all ~30 call sites are untyped `any`.
- **54 orphaned SVGs** in `src/assets/scribbl/` (avatar presets, stickers). Runtime loads a *separate* copy from `public/scribbl/stickers/`. Also 2 orphaned components (`ScribbleActions.tsx`, `ScribbleNotePanel.tsx`).

> Correction to a likely assumption: **`src/` is not dead code.** It's a live feature-slice tree (`src/features/`, `src/assets/`) imported by 12 files via `@/src/...`. There is no `src/app/`, so there's no competing route tree. 35 of 37 files are reachable.
